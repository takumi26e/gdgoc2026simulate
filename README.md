# コンビニ立体音響シミュレーター

視覚障害のある人がコンビニで買い物をするときの、音の案内を試すための仮想の店です。PC でキャラクターを動かし、スマホの角度を頭の向きにして、スマホのイヤホンで立体音響を聞きます。カメラの認識と店の 3D 地図は、精度が出ている前提で作っています。

## 動かし方

Node.js 22.12 以上が必要です。

```
npm install
npm run dev
```

表示された URL を開きます。自己署名証明書の警告が出たら、詳細設定から続行してください。

- PC: `https://localhost:8443/pc.html`
- スマホ: `https://<PC の IP アドレス>:8443/phone.html`（PC と同じネットワークにつなぐ）

スマホで「開始」を押し、モーションセンサーを許可します。ファイルを直すとページが自動で読み込み直されるので、スマホでもう一度「開始」を押します。

大学や会社の Wi-Fi は端末どうしの通信を止めていることがあります。そのときは、スマホのテザリングに PC をつなぎます。

## 操作

| 担当 | 操作 |
|---|---|
| PC | 歩く（W/S/A/D）、案内（G）、音の道（T）、方式（1/2/3）、視点（V）、読み上げのオン・オフ、設定 |
| PC のマウス | 手の向き。左ボタンで指さし、Shift でパー、C で手のひらの開閉（指した島へ案内） |
| スマホの角度 | 左右の向き（PC では変えられない）。聞こえ方、歩く方向、認識する範囲が変わる |
| スマホのスライド | 触れた点から上へで前、下へで後ろ |
| スマホのボタン | 話す（押しているあいだ Gemini に話しかける）、音の道（短く押すと 1 回、長押しで繰り返し）、パー、指さし（押しているあいだ） |

## 鳴り方

- **読み上げ**: オンのあいだ、スマホの画面に写っていて、4m 以内で、商品の面を正面から左右 70° 以内で見ている物のうち、いちばん近い 1 つの名前を繰り返します。PC のパネルか、Gemini に「読み上げを止めて」で切り替えます。
- **抽象度**: 棚と商品の 2 つです。棚まで 1m より近いと、画面のまん中に近い商品の名前、遠いと棚の名前です。
- **パーと指さし**: 手を向けた先の 1 つ。パーは距離で棚か商品、指さしはいつも商品です。
- **音の道**: 通路を横 4 本と縦 2 本の道とし、いちばん近い道の上から、行ける方向へ「ポ・コ・ピン」と音が遠ざかります。方向ごとに音の種類と鳴り始めが違います。
- **案内**: 行き先の島の名前と、次の曲がり角のピコピコ音。正面に向くと音が高くなります。
- **店の中の人**: 店員、レジに並ぶ人などが立ち、3 人が歩き回ります。今は見た目だけです。

立体音響は、Resonance Audio（Google）、KEMAR の実測 HRTF、ブラウザ標準の 3 つから選べます。

## Gemini に話しかける

スマホの「話す」を押しているあいだ、Gemini Live API に話しかけられます。Gemini の声は、店の音を小さくして頭の中で鳴ります。

- 「お茶の棚に行きたい」「ツナマヨはどこ？」: 音の道の通路だけを通る経路で、次の地点をピコピコ鳴らします。地点に着くたびに、Gemini が次の地点の方向と距離を伝えます。
- 「周りに何がある？」: 6m 以内の棚・場所・人を、時計の方向と距離で答えます。
- 「読み上げを止めて」「読み上げて」: 読み上げのオン・オフ。

API キーは、`simulator/.gemini-key` に 1 行で書くか、環境変数 `GEMINI_API_KEY` に入れます。キーはサーバーだけが持ち、ページには渡しません（`.gemini-key` は git に入りません）。使うモデルは `src/voice/gemini.ts` の `MODEL` です。

## 構成

```
src/
  main.ts           入口と毎フレームの処理
  config.ts         調整できる値（距離、角度、音量など）
  core/             ブラウザなしで動く計算（テストあり）
    store.ts          店のデータ → 島・棚・カテゴリ・商品の木
    geometry.ts       面の上の計算、歩けるか、読み取れる角度
    route.ts          案内の経路
    roads.ts          音の道
    gesture.ts        手の形の判定
    kemar.ts          HRTF の選び方
  shop.ts           この店（store.json から作る）
  world.ts          3D の店、人、カメラ
  sim/              認識、手、案内、音の道の表示、店の中の人、スマホの向き
  audio/
    engine.ts         立体音響、ボイス、音の道を鳴らす
    select.ts         そのとき鳴らす物を選ぶ
  ui/               PC のパネル、スマホの画面、キーとマウス、表示
  voice/            Gemini Live API（会話、マイク、Gemini が呼ぶ関数）
  link.ts, sync.ts  PC とスマホの同期（WebSocket）
  data/             店（store.json）、音声の一覧（sounds.json）、HRIR（kemar.json）
public/sounds/      読み上げの音声（WAV）
server/relay.ts     開発用サーバーに足す証明書と、同期と Gemini の中継
tools/              音声と HRIR を作るスクリプト
tests/              core のテスト
```

## 店を直す

`src/data/store.json` を直したら、音声を作り直します。商品は「表示名|読み」と書くと、読みで読み上げます。

```
py -I tools/build_assets.py        # Windows（Microsoft Haruka）
python3 -I tools/build_assets.py   # macOS（Kyoko）
```

どちらで作っても全部を作り直すので、声は混ざりません。

## 確かめる

```
npm test          # core のテスト
npm run check     # 型の検査
npm run build     # 本番用にまとめる（npm run preview で確かめられる）
```

## クレジット

- 立体音響: [Resonance Audio](https://resonance-audio.github.io/resonance-audio/)（Google、Apache 2.0）
- HRIR: MIT Media Lab の KEMAR 測定データ（Bill Gardner、Keith Martin、1994）
- 手の認識: MediaPipe Hand Landmarker（Google）
- 音声: Windows の読み上げ音声（Microsoft Haruka）で作りました。非営利の試作としてだけ使っています。
